# Архитектура агента

Документ описывает реализацию в `agent.py` и `agent_core/` на коммите `f11ae2d`
(код заморожен). Политика по умолчанию — **v4** (`agent.POLICY = "v4"`); прежняя
политика v3 (confirmation gate) сохранена в коде и включается `POLICY = "v3"`.

## Цикл агента (v4)

```mermaid
flowchart TD
    A[Agent.act(env)] --> B[safety net: try/except вокруг _act]
    B --> C[Подключить priors_history.get_prior]
    C --> D[build_cells: ячейки tariff × arpu_segment]
    D --> E[ExplorerV4.candidates: одна upsell-цель на ячейку, ранг prior × size × ARPU]
    E --> F[Раунд 1: топ-10 ячеек, sms n=150, самый дешёвый срез]
    F --> G[Подтверждение: топ-3 по наблюдённому ratio, n=200, до 5 пилотов]
    G --> H[Остаток пилотов: скрининг следующих неисследованных ячеек, n=150]
    H --> I[PlannerV4.qualifying: pooled pilot > 0 и posterior mean > 0]
    I --> J[Канал и размер по экономике планировщика; лимиты reach/money/5000/10]
    J --> K{Есть кампании?}
    K -->|да| L[Вернуть до 10 кампаний, по одной на ячейку]
    K -->|нет| M[Fallback: кампания, не задевающая никого]
    L --> N{AGENT_USE_LLM=1 и ключ?}
    M --> N
    N -->|да| O[review_finals: может только удалить]
    N -->|нет| P[Вернуть список]
```

## Политика v4 (`agent_core/v4.py`)

### Пилоты

1. **Одна цель на ячейку.** Для каждой ячейки `(current_tariff, arpu_segment)`
   берутся только тарифы **дороже текущего** (`price_tariff` из `env.tariffs`) — даунгрейды
   не пилотируются никогда. Среди них выбирается тариф с наибольшим prior mean; при
   равенстве — ближайший по цене. Ячейки с отрицательным prior лучшей цели пропускаются.
2. **Ранжирование ячеек** — `prior × size × mean predicted_arpu` (ожидаемая ценность);
   ячейки с prior = 0 (нет истории) идут после положительных, по `size × ARPU`.
   Допускаются ячейки от `MIN_CELL_SIZE = 300` клиентов; если таких нет вовсе —
   от `MIN_PILOT_CELL = 10` (минимальный пилот среды).
3. **Раунд 1:** `V4_ROUND1_PILOTS = 10` ячеек, канал sms, `ROUND1_N = 150`.
   При `CHEAP_SLICE_PILOTS = True` пилот идёт на срез ячейки по `data_segment` или
   `call_segment` с наименьшим средним `predicted_arpu` среди срезов размером ≥ n:
   эффект зависит только от ячейки (MECHANICS.md §1), поэтому сигнал тот же, а
   реализованный убыток/прибыль пилота меньше. Если sms недоступен по деньгам,
   пилот идёт на бесплатный push.
4. **Подтверждение (winner's-curse check):** `V4_RECHECK_ARMS = 3` лучших по
   наблюдённому ratio (только положительные) получают второй пилот `ROUND2_N = 200`;
   оставшиеся из `V4_RECHECK_PILOTS = 5` идут лучшим по pooled-оценке, пока она > 0.
5. **Остаток пилотов** (`V4_SCREEN_LEFTOVER = True`): все ещё не потраченные пилоты
   идут на скрининг следующих по рангу **неисследованных** ячеек — любых, которые
   могут вместить один пилот (≥ `ROUND1_N` клиентов), n=150. Первые 15 пилотов при
   этом не меняются; см. анализ разрыва с оракулом в коммите `f11ae2d`.

Каждый пилот обновляет `Posterior` (normal-normal, шум `0.804/√n/mult`) и отдельно
pooled-оценку только по пилотам (`Posterior.pilot_only`, prior игнорируется).

### Финальные кампании

`PlannerV4.qualifying`: для каждой ячейки — цель с наибольшим posterior mean среди
испытанных, при условии **pooled pilot estimate > 0 и posterior mean > 0**. Порядок
ячеек — по ожидаемому суммарному net всей ячейки (`_rank_value`), затем `Planner.plan`:
канал и число контактов подбираются перебором каналов (`_best_assignment`) под
`env.remaining_contacts`, `env.remaining_budget`, 5 000 контактов на кампанию и
10 кампаний; ценность считается по клиентам с наименьшими ID (скоринг обрезает
именно их). Одна кампания на ячейку — сегменты не пересекаются. `SPLIT_COLUMNS = ()`:
разбиение ячейки на подсегменты с разными каналами выключено (на stress_eval оно
усиливало ложноположительную ячейку).

### Fallback и safety net

- **Нечего запускать** (ни одна пара не прошла отбор): если лучший posterior mean > 0 —
  push на самый маленький срез `(data_segment, call_segment)` этой ячейки; иначе
  (в т.ч. пусто протестировано / пустая аудитория) — `safety_campaign(env)`:
  схемно-корректная push-кампания с легальными фильтрами (известный тариф, значения
  arpu/data/call-сегментов из `SEGMENT_VALUES`), которые **не совпадают ни с одним
  клиентом** (`zero_customer_campaign`); если такой комбинации нет — глобально
  самый маленький срез на push. Обязательная кампания есть, стоимость — ноль.
- **`Agent.act` никогда не бросает исключений:** `_act` обёрнут в `try/except`; при
  любой ошибке она логируется и возвращается одна `safety_campaign`. Пустая аудитория,
  ячейки < 300 клиентов, нулевой бюджет — покрыты `tests/test_hardening.py`.

## Политика v3 (`Explorer`, `Planner`) — выключена

Хранится для сравнения (`POLICY = "v3"`): по две цели на ячейку (`ROUND1_PER_CELL = 2`),
подтверждение лидеров, финал только при `confirmed_enough` (≥ 2 пилота или ≥ 300
клиентов) и `mean − 1.5·sd > 0` (`FINAL_K`), не более `MAX_PILOTS_PER_ARM = 2` пилотов
на пару. `ADAPTIVE_STOP = False` — ранняя остановка разведки выключена (не улучшала
худший прогон). Сравнение v3/v4/naive/oracle — `tools/benchmark.py`, `docs/BENCHMARK.md`.

## Переключатели (текущие значения)

| Переключатель | Файл | Значение | Смысл |
|---|---|---|---|
| `POLICY` | `agent.py` | `"v4"` | политика агента; `"v3"` — confirmation gate |
| `V4_SCREEN_LEFTOVER` | `agent_core/v4.py` | `True` | остаток пилотов на скрининг новых ячеек |
| `CHEAP_SLICE_PILOTS` | `agent_core/explorer.py` | `True` | пилот на самом дешёвом срезе ячейки |
| `SPLIT_COLUMNS` | `agent_core/planner.py` | `()` | разбиение финалов на подсегменты выключено |
| `ADAPTIVE_STOP` | `agent_core/explorer.py` | `False` | ранняя остановка разведки (v3), выключена |

Константы: `V4_ROUND1_PILOTS = 10`, `V4_RECHECK_ARMS = 3`, `V4_RECHECK_PILOTS = 5`,
`ROUND1_N = 150`, `ROUND2_N = 200`, `MIN_CELL_SIZE = 300`, `MIN_PILOT_CELL = 10`.

## Модули `agent_core`

- **`cells.py`** — `build_cells(profile)`: `{(tariff, segment): {size, arpu}}`.
- **`priors.py`** — подключаемый источник prior: `set_prior_source(fn)`, `get_prior`.
- **`priors_history.py`** — prior базового эффекта из `data/change_tariff.csv`
  (формулы — `docs/PRIORS.md`). Файл ищется относительно модуля, затем в
  `Path.cwd()/data`; если не найден — **предупреждение в лог** и prior `(0, 0.1)` для
  всех пар (тогда v4 пилотирует ближайшие по цене апселлы; `tests/test_no_history.py`).
- **`bayes.py`** — `Posterior`: `get/update/lcb/ucb`, `confirmed_enough`, `pilot_only`.
- **`explorer.py`** — базовый разведчик (v3): кандидаты, пилот на срезе, выбор канала
  пилота (`_pilot_channel`), таблица posterior для советника.
- **`planner.py`** — экономика финалов (`_channel_options`, `_contacts`,
  `_best_assignment`), `qualifying` v3, fallback, `zero_customer_campaign`,
  `safety_campaign`.
- **`v4.py`** — `ExplorerV4`, `PlannerV4` (см. выше).
- **`llm_advisor.py`** — опциональный советник (ниже).

## LLM-советник (`agent_core/llm_advisor.py`)

Включается **только** при `AGENT_USE_LLM=1` **и** непустом `OPENAI_API_KEY`
(`OPENAI_MODEL`, по умолчанию `gpt-5.6-luna`; `OPENAI_BASE_URL`). Ключ без флага
ничего не меняет — агент остаётся полностью детерминированным. Без советника
`make_submission.py` воспроизводим; с ним — нет (модель не принимает `temperature=0`).

Что может: после раунда пилотов переставить порядок подтверждения **только внутри
наших топ-6** и пометить подозрительные пары; после планировщика — **только удалить**
финальные кампании по имени (не все сразу). Добавлять/менять кампании не может.

Ограничения: JSON Schema в ответе; `temperature=0`, при отказе модели — один повтор без
него (логируется); **жёсткий дедлайн `TIMEOUT_S = 20` с** на весь вызов, включая чтение
тела — вызов выполняется в daemon-потоке, по истечении поток бросается и применяется
детерминированное решение; не более `MAX_CALLS = 3` вызовов и `TIME_BUDGET_S = 90` с
суммарно на запуск. Любая ошибка, таймаут, неверный JSON → наше решение без изменений.
Все решения и ошибки — в `advisor.log` и в логгере. Гардрейлы покрыты
`tests/test_llm_advisor.py`, `tests/test_hardening.py`.

## Сборка и проверки

- `dist/agent_single.py` — однофайловая сборка (`tools/bundle_agent.py`);
  `tests/test_bundle.py` падает, если сборка устарела.
- `tools/stress_eval.py` — 6 вариантов искажённых эффектов × 10 seeds;
  `tools/benchmark.py` — template / naive / ours / v4 / oracle. Цифры на `f11ae2d`:
  baseline медиана 3 541 278, минимум 1 759 226, 10/10; stress 50/50, худший +604 754.
